Pre-sale verification — worked examples

Five request/response pairs covering every status the contract can return. Each file also records what an agent may say to a shopper and what it must not — because the response being correct is only half of getting this right.

eligible

Every check passed

Licensed seller, open destination, age verified, under the volume limit. Still a snapshot — expires_at is binding and checkout re-verifies.

ineligible

Destination prohibits DTC entirely

Terminal. next_actions is empty because nothing the buyer does changes the answer.

requires_buyer_input

Age verification missing — the first inversion

The enforcement API treats this as a hard block because an order already exists by then. Pre-sale is earlier, where the honest answer is “not yet”.

requires_merchant_review

Referred to a human at the merchant

Reserved. No rule produces a soft_block today, so this case is specified but not yet reachable in production.

retry

No decision was reached — the second inversion

Note checks_performed is empty. Nothing was evaluated. The enforcement API fails open here because a human reviews the order; an agent has no such backstop.
Reading these. Branch on status and nothing else. reason_codes are for logging and optional detail; next_actions tell you what to do next; messages are not stable and should never be parsed. The prefix on a reason code carries meaning — seller_* never generalises to other sellers, destination_* does. See verdicts and reason codes.
